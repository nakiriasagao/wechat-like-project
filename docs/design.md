# 业务设计文档 — 类微信聊天软件（Group Chat Project）

> 本文件记录产品的业务范围、角色权限矩阵与关键业务流程，是团队协作的**事实来源**。
> `AGENTS.md` 只引用本文件的要点；任何影响权限或状态机的改动，必须同步更新本文件。

## 1. 产品范围与重点

### 1.1 明确的重点模块（需做深做透）
- 单聊 / 群聊会话（未读数、置顶、免打扰、消息撤回、引用、回复、@）
- 消息类型：文字、表情、图片、文件、语音；**模拟**发送即可，但撤回/删除/本地缓存要真实。
- 好友关系链：添加好友、好友申请、黑名单、删除好友的联动（互删 vs 单向删除）。
- **群组治理**（核心深挖）：建群、邀请、退群、踢人、转让群主、设置管理员、禁言、全员禁言、群公告、解散群；群主/管理员/普通成员权限差异。
- **内容安全与举报**（核心联动）：举报消息/用户/群 → 平台客服审核 → 处罚（封禁/禁言/删消息/解散群）→ 申诉 → 终裁。
- **多端同步**：用户端（Web / App / 小程序）、管理员后台、超级管理员后台。至少两个端要真实落地，其余可做简化版。

### 1.2 可模拟 / 可省略的模块
- 真实支付、真实短信验证码、真正的长连接消息推送（用 WebSocket + 固定轮询兜底的简化版）。
- 视频号 / 朋友圈 / 公众号 / 小程序，默认不实现。

### 1.3 判定原则
> "只要决定做某块内容，就要把它做全做扎实；不做就明确不做。"

## 3. 关键业务流程（做深做透的清单）

每个流程都应画出状态机，覆盖正常流 + 异常分支 + 超时 + 角色介入。

### 3.1 举报 → 审核 → 处罚 → 申诉（核心联动）
1. 用户对消息/用户/群发起举报，选择类别（骚扰、广告、违法、涉黄、诈骗等）并附证据；
2. 举报生成工单，进入"待处理"；
3. 平台客服初审：合规打回（通知举报人）、转办、或建议处罚；
4. 若需处罚 → 平台管理员终裁：禁言（1/7/30天）、封号、冻结群、解散群、删除消息、踢出成员；
5. 被处罚方收到通知，可**申诉**，进入复核；
6. 平台管理员复核：维持、减轻、撤销；每次处置均可追溯操作日志；
7. 要求：所有状态变更留痕（谁、何时、做了什么、原因）。

### 3.2 群聊治理状态机
- 建群：创建者默认成为群主；邀请需对方同意（或允许直接拉入需在设置中声明）。
- 退群/被移出：消息保留但该成员失去权限；群主退群需先**转让**或由规则决定解散。
- 禁言：管理员/群主可对成员禁言；可全员禁言；禁言状态需即时体现在发送接口的守卫上。
- 解散群：仅群主/超管可操作，完成后需确认历史记录处理策略。

### 3.3 好友关系链
- 添加好友：搜索 → 发申请 → 对方同意/拒绝 → 互为好友。
- 删除好友：明确"单向删除"还是"互相删除"；被删方是否还能看到历史消息；是否从对方列表移除（双向 vs 单向）。
- 黑名单：拉黑后对方不可发消息、不可看动态；解黑恢复的边界。

### 3.4 消息生命周期
- 发送 → 送达 → 已读（回执策略）→ 撤回（时限内）→ 删除（本地/双方）→ 过期（如语音时长限制）。
- 未读计数：围绕"最后一条已读消息"计算，含群聊按成员维度。

### 3.5 会话列表
- 置顶、免打扰、删除会话、新增好友/建群自动插入会话、折叠会话（如群太多）。

## 4. 建议目录结构

> 若小组已定方案，保持一致并更新本节。

```
src/
  modules/
    auth/          # 登录、鉴权、会话
    friend/        # 好友关系、申请、黑名单
    conversation/  # 会话、未读数、置顶、免打扰
    message/       # 消息、撤回、回执
    group/         # 群组、成员、权限、禁言
    report/        # 举报工单、审核、处罚
    admin/         # 客服/管理员/超管后台
  common/          # 通用守卫、异常、日志、常量
  shared/          # 类型、枚举、权限矩阵定义（单源）
```
